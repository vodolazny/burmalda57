# 📚 Электронный дневник obr57 (burmalda57) — Web

Неофициальный **веб-клиент** электронного дневника Орловской области ([obr57.ru](https://obr57.ru/gis)).
Ядро написано на **Rust**, интерфейс — [Slint](https://slint.dev), всё компилируется в **WebAssembly** и работает прямо в браузере.

Есть два режима: **демо** (без входа, тестовые данные, работает на любом статическом хостинге) и **полная версия** со входом и настоящими данными — ей нужен **свой прокси на сервере**, см. [Полная версия](#-полная-версия-свой-сервер-с-прокси).

Это часть [монорепозитория burmalda57](../../README.md): общая бизнес-логика
живёт в [`crates/core`](../../crates/core), а в этом крейте остаются только
браузерные адаптеры и desktop-UI.

> ⚠️ **Неофициальный проект.** Не связан с Департаментом образования Орловской области, порталом Госуслуг/ЕСИА или разработчиками официального дневника. Используется на свой страх и риск.

## ✨ Возможности

- 📊 Оценки по предметам: периоды, веса, средние баллы
- 📈 Графики успеваемости
- 📅 Дневник, расписание и домашние задания
- 🎓 Итоговые оценки за периоды
- 🗓️ Свои события
- 👤 Профиль: ФИО, школа, класс
- 🌙 Ночной режим (следует системной теме)
- 📝 Локальные заметки к урокам с автосохранением в деталях урока
- 👁 Скрытие предметов из дневника через профиль → «Предметы в дневнике»

На телефоне используется тот же интерфейс, что в Android: раскрывающиеся
карточки уроков и нижняя навигация. Он также включается в узком окне браузера
(менее 760 px). На ПК остаётся интерфейс с боковой навигацией; вход отображается
в карточке по центру экрана.

Заметки и список скрытых предметов шифруются и сохраняются в этом браузере.
Они не синхронизируются с мобильным приложением или другим браузером.
Скрытие влияет на расписание, но не удаляет оценки по предмету.

## 🔒 Приватность и безопасность

- **Пароль от Госуслуг приложение не видит и не хранит.** Логин и пароль ты
  вводишь на настоящей странице госуслуг; приложение использует только
  сессионную куку `X1_SSO`, которую пользователь вставляет в окно входа.
- **Сессия хранится на клиенте шифрованно (envelope encryption, как было с
  Android Keystore):**
  - данные (сессия, кеши дневника, отметки ДЗ) шифруются **AES-256-GCM**;
  - ключ шифрования данных (DEK) генерируется случайно и **заворачивается
    неизвлекаемым ключом KEK** из `window.crypto.subtle` — у KEK стоит
    `extractable = false`, экспортировать его из браузера невозможно;
  - KEK живёт в **IndexedDB**, завёрнутый DEK — в localStorage; сам DEK в
    открытом виде никогда не попадает на диск;
  - **Web Locks** сериализует первичное создание ключей между вкладками;
  - HKDF-SHA256 разделяет ключи по назначению (сессия / кеши).
- **Данные уходят только на серверы дневника** (`mp2.obr57.ru`), у приложения
  нет своих бэкендов. В полной версии запросы идут через **ваш прокси**: он
  видит весь трафик, включая сессионные данные, поэтому разворачивайте
  собственный и не пользуйтесь чужим. Телеметрии нет.
- Никакой рекламы, трекеров и аналитики поведения.
- «Выйти» стирает сессию и все серверные кеши из хранилища браузера.

### Почему нужен прокси

Браузер не может обратиться к `mp2.obr57.ru` напрямую: сервер не отдаёт
CORS-заголовки, браузер не даёт задать `User-Agent`, который отправляют
мобильные приложения, а часть запросов отклоняется по IP. Прокси решает это
сразу. Адрес
передаётся параметром `?proxy=`, и запросы идут на `<proxy>/journals/...`,
`<proxy>/session/...` вместо `https://mp2.obr57.ru/...`.
Разрешён только прокси на том же origin (схема, домен и порт), например
`?proxy=/api`. Внешний адрес блокируется до восстановления сессии;
HTTP-перенаправления API не выполняются.

Для входа и сохранения данных нужен современный браузер с WebCrypto,
IndexedDB и Web Locks, а также HTTPS (при локальной разработке — localhost).

## 🛠️ Технологии

| Слой | Что используется |
|------|------------------|
| UI | Slint 1.x (рендер `renderer-femtovg`, WebGL) |
| Логика/сеть/крипта | Rust → WebAssembly |
| Сеть | браузерный `fetch` + `AbortController` (таймауты) |
| Async | `wasm-bindgen-futures` (однопоточно, `spawn_local`) |
| Крипта | Web Crypto (KEK) + `aes-gcm`/`hkdf`/`sha2` (данные) |
| Хранилище | localStorage (шифрованные записи) + IndexedDB (KEK) |

## 📦 Сборка из исходников

### Требования

- **Rust** (stable) + wasm-таргет:
  ```bash
  rustup target add wasm32-unknown-unknown
  ```
- **wasm-bindgen-cli** (версия должна совпадать с версией крейта
  `wasm-bindgen` в корневом `Cargo.lock`):
  ```bash
  cargo install wasm-bindgen-cli --version 0.2.130 --locked
  ```

### Сборка

**Windows (PowerShell):**
```powershell
.\build_web.ps1              # полная версия со входом
.\build_web.ps1 -DemoOnly    # демо: без входа и сети
```

**Linux / macOS:**
```bash
./build_web.sh               # полная версия со входом
./build_web.sh --demo-only   # демо: без входа и сети
```

Или вручную (из `apps/web`):
```bash
cargo build --release --target wasm32-unknown-unknown -p burmalda57-web
wasm-bindgen ../../target/wasm32-unknown-unknown/release/burmalda57.wasm \
    --out-dir web/pkg --target web --remove-name-section
```
Для демо-сборки добавьте к `cargo build` флаг `--features demo-only`: она
сразу открывает демо и отключает вход, выход и запросы к API.

### Запуск демо локально

`file://` не подходит — нужен любой статический HTTP-сервер. Для
демо-сборки (`--demo-only`) подойдёт даже встроенный в Python:
```bash
cd web
python -m http.server 8080
```
Открой [http://localhost:8080](http://localhost:8080).

> **Python-сервер — только для демо.** Он лишь раздаёт файлы и ничего не
> проксирует. Со сборкой, в которой включён вход, API через него не заработает
> (CORS), а `?proxy=` нечем обслужить. Для полной версии нужен настоящий
> сервер с прокси — следующий раздел.

### Публичный демо-стенд

GitHub Pages собирает версию с `--features demo-only`: она сразу открывает
демо и не показывает вход, потому что с публичного хостинга запросы к
`mp2.obr57.ru` блокируются CORS и ограничениями по IP. Стенд доступен на
[burmalda57.redhatgcc.ru](https://burmalda57.redhatgcc.ru/) и пересобирается при
каждом push в `main`.

## 🌐 Полная версия: свой сервер с прокси

Схема: один домен отдаёт и статику (`index.html` + `pkg/`), и прокси на
`mp2.obr57.ru` по пути `/api/`. Так браузер видит всё как один origin, и
CORS-заголовки не нужны.

```
браузер ──→ https://diary.example.com/            (статика: index.html, pkg/)
        └─→ https://diary.example.com/api/...  ──→  https://mp2.obr57.ru/...
```

### Что нужно

- **Сервер с публичным IP и доменом** (VPS). Дневник может отклонять запросы
  по IP (в `core` статусы 407/429/451 трактуются как отказ по IP или VPN),
  поэтому, если API отвечает ошибкой «Журнал не пускает», попробуйте сервер с
  другим, лучше российским, IP.
- **HTTPS.** Страница на `https://` не может обращаться к `http://`-прокси
  (mixed content), так что сертификат обязателен. Caddy выпускает его сам,
  для nginx — Let's Encrypt (`certbot`).
- **Полная сборка** (без `--demo-only`).

### 1. Собрать и загрузить

```bash
./build_web.sh            # из apps/web; результат — web/index.html и web/pkg/
rsync -av --delete web/ user@server:/var/www/burmalda57/
```

### 2. Настроить сервер

#### Вариант A — Caddy (проще: HTTPS автоматически)

`/etc/caddy/Caddyfile`:

```caddy
diary.example.com {
    # Прокси к API дневника
    handle_path /api/* {
        reverse_proxy https://mp2.obr57.ru {
            header_up Host {upstream_hostport}
            header_up User-Agent "Dalvik/2.1.0 (Linux; U; Android 13)"
            header_up -Origin
            header_up -Referer
        }
    }

    # Статика
    handle {
        root * /var/www/burmalda57
        file_server
    }
}
```

```bash
sudo systemctl reload caddy
```

#### Вариант Б — nginx

`/etc/nginx/conf.d/burmalda57.conf`:

```nginx
server {
    listen 443 ssl;
    server_name diary.example.com;

    ssl_certificate     /etc/letsencrypt/live/diary.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/diary.example.com/privkey.pem;

    root /var/www/burmalda57;
    index index.html;

    # Статика
    location / {
        try_files $uri $uri/ =404;
    }

    # Прокси к API дневника: /api/journals/login -> https://mp2.obr57.ru/journals/login
    location /api/ {
        proxy_pass https://mp2.obr57.ru/;
        proxy_ssl_server_name on;
        proxy_set_header Host mp2.obr57.ru;
        proxy_set_header User-Agent "Dalvik/2.1.0 (Linux; U; Android 13)";
        proxy_set_header Origin "";
        proxy_set_header Referer "";
        proxy_read_timeout 60s;
    }
}

server {
    listen 80;
    server_name diary.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Если в консоли браузера жалобы на MIME-тип `.wasm`, добавьте в `server`:
`types { application/wasm wasm; }`.

### 3. Открыть с параметром `?proxy=`

```
https://diary.example.com/?proxy=/api
```

Параметр читается при загрузке страницы, поэтому добавьте адрес в закладки.
Без `?proxy=` клиент пойдёт прямо на `mp2.obr57.ru` и упрётся в CORS.

### 4. Войти

Нажми «Войти» и вставь значение cookie `X1_SSO` (см. окно с подсказкой): его
берут на [obr57.ru/gis](https://obr57.ru/gis) после входа через Госуслуги.
Дальше всё как в мобильном приложении, включая выбор ребёнка для родительских
аккаунтов. Демо-режим доступен и без входа.

### Зачем в конфиге `User-Agent`, `Origin` и `Referer`

Мобильные приложения шлют `User-Agent: Dalvik/2.1.0 (Linux; U; Android 13)` и
не шлют `Origin`/`Referer`. Браузер не позволяет подменить `User-Agent` и сам
добавляет `Origin`, поэтому прокси приводит запрос к виду, привычному для
мобильных клиентов.

### Безопасность

- Прокси закреплён за `mp2.obr57.ru` и не является открытым, но любой, кто
  знает адрес, может гонять через ваш сервер запросы к дневнику. При
  необходимости закройте доступ (`allow`/`deny` в nginx, `basic_auth` в Caddy)
  или ограничьте частоту запросов.
- Через прокси проходят сессионные данные (`apikey`, `X1_SSO`). Не логируйте
  тела запросов и не отдавайте доступ к серверу посторонним.
- Если статика и прокси стоят на **разных** доменах, прокси должен сам
  отвечать на preflight `OPTIONS` и отдавать `Access-Control-Allow-Origin`,
  `Access-Control-Allow-Methods: POST, GET, OPTIONS` и
  `Access-Control-Allow-Headers: Content-Type, X-Requested-With`. Проще держать
  всё на одном домене, как выше.

### Если не работает

| Симптом | Причина и решение |
|---|---|
| «Нет связи — проверьте сеть или VPN» | страница открыта без `?proxy=` или адрес прокси неверен; проверьте вкладку Network в DevTools |
| «Журнал не пускает» (407/429/451) | дневник отклонил IP сервера; попробуйте сервер с другим IP |
| «Сессия истекла — войдите заново» (401/403) | устарела кука `X1_SSO` — войдите заново и вставьте свежую |
| Ошибка mixed content | страница на `https://`, а прокси указан как `http://` — используйте HTTPS |
| Белый экран, ошибка загрузки wasm | не загружена `pkg/` или открыто по `file://` — проверьте, что `pkg/` лежит рядом с `index.html` |

## 🗂️ Структура проекта

```
.
├── Cargo.toml                # зависимости Rust и профили оптимизации
├── build.rs                  # компиляция ui/app.slint
├── src/                      # платформенные адаптеры и маппинг core → Slint:
│                             # app, http (fetch), secure_storage (WebCrypto),
│                             # platform, theme, ui_bridge
├── ui/app.slint              # веб-интерфейс на Slint (M3 Navigation Rail)
├── web/
│   ├── index.html            # страница приложения
│   └── pkg/                  # сгенерированные wasm-bindgen файлы (.wasm, .js)
├── build_web.sh              # скрипт сборки под Linux/macOS
├── build_web.ps1             # скрипт сборки под Windows PowerShell
└── README.md
```

Бизнес-логика (вход, дневник, оценки, кэши, шифрование) живёт в общем
`crates/core`; web-крейт содержит только браузерные адаптеры и интерфейс.
